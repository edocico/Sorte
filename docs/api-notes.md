# API notes for the pinned crates

First checked on 2026-11-05 against the published sources of slint 1.18.1, vello 0.11.0, vello_cpu 0.3.0, wgpu-types 30.0.1, rand 0.10.3 and kira 0.12.6 (read, never built). The same day the M0 spike (`spike/`) built and ran all of them, with wgpu 30.0.1, parley 0.12.0 and winit 0.30.13, on Fedora 45 / GNOME Wayland with an AMD Radeon 780M (RADV), an NVIDIA RTX 4060 laptop GPU and llvmpipe, panel 2560×1600 at 165 Hz, scale 1.667. Lines marked "spike" were confirmed by the compiler or at runtime there; the rest are read from source. Paths are inside each crate's archive. Re-check after any version bump; Windows, macOS and X11 without XWayland are not run yet.

## Slint and wgpu

- The bridge is the `unstable-wgpu-30` feature of `slint`. It enables `slint::wgpu_30` (re-exporting the wgpu crate, `WGPUConfiguration`, `WGPUSettings`, `TextureImportError`) and `GraphicsAPI::WGPU30`. `slint::wgpu_30::wgpu` is the same crate as a direct `wgpu = "30.0.1"` dependency. (slint-1.18.1/lib.rs:546–661; Cargo.toml:370–374)
- A wgpu renderer must be enabled too: `renderer-femtovg-wgpu`. Without it (or a skia feature) window creation fails with "unstable-wgpu-30 was enabled but no renderer was selected". It also becomes the default renderer and drops GL FemtoVG from the automatic fallback list; GL stays reachable with `renderer_name("femtovg")`. Spike: `["unstable-wgpu-30", "unstable-winit-030", "renderer-femtovg-wgpu"]` on top of the defaults. (i-slint-backend-winit-1.18.1/lib.rs:139–181, 1330–1341)
- Select it with `slint::BackendSelector::new().require_wgpu_30(config).select()`. `WGPUConfiguration::Manual { instance, adapter, device, queue }` takes owned handles, all cheap Arc clones: pass clones and keep yours for Vello. With Manual, Slint creates the window surface from your instance and calls `surface.get_default_config(&adapter, ..).unwrap()`, so it panics if your adapter cannot present to the window. Spike: works on RADV and on the NVIDIA dGPU through PRIME. (i-slint-core-1.18.1/graphics/wgpu_30.rs:74–99, 321–331; i-slint-renderer-femtovg-1.18.1/wgpu.rs:407–408)
- `WGPUSettings::default()` requests `Limits::downlevel_webgl2_defaults()`, with zero compute and storage limits: Vello fails on it ("Too many bindings of type StorageBuffers in Stage COMPUTE, limit is 0"), and on `downlevel_defaults()` too. Create the device yourself with `wgpu::Limits::default().using_resolution(adapter.limits())` (the resolution part: the default 8192 max texture size rejects larger surfaces) and `Features::empty()`; neither Slint nor FemtoVG needs more. Spike. (i-slint-core-1.18.1/graphics/wgpu_30.rs:66)
- `select()` with Manual does not vet your adapter: it passes when any adapter of the instance is not `DeviceType::Cpu`. Check `adapter.get_info().device_type` yourself before choosing the wgpu path. llvmpipe reports as a CPU adapter; on a machine with only CPU adapters `select()` fails ("Set SLINT_WGPU_CPU=1 to allow CPU adapters"), and then no platform is set, so a second `BackendSelector` (for example `renderer_name("femtovg")` or `"software"`) succeeds. Spike. (i-slint-backend-selector-1.18.1/api.rs:306–324; wgpu_30.rs:180–241)
- Create the instance with `Backends::PRIMARY` (Slint's own init avoids GL for "rendering artifacts"); `InstanceDescriptor::new_without_display_handle_from_env()` is fine, and `wgpu::util::initialize_adapter_from_env_or_default` honours `WGPU_ADAPTER_NAME` and `WGPU_POWER_PREF`. Spike.
- Debug builds abort at exit ("cannot access a Thread Local Storage value during or after destruction") unless the queue is used once before `select()`: call `queue.submit([])`. Slint's thread-local context drops the queue after wgpu-core's debug lock tracer. Release builds are unaffected. Spike.
- Texture import: `impl TryFrom<wgpu::Texture> for slint::Image` needs format `Rgba8Unorm` or `Rgba8UnormSrgb` and usage `TEXTURE_BINDING | RENDER_ATTACHMENT`. Import **`Rgba8Unorm`**: FemtoVG-wgpu uses a non-sRGB surface and samples raw values, so an `Rgba8UnormSrgb` texture shows too dark (bytes 128 come out as 55). It expects straight alpha and premultiplies itself, which is what Vello writes. With Vello the usage is `STORAGE_BINDING | TEXTURE_BINDING | RENDER_ATTACHMENT`. An Image set before Slint draws shows in that same frame. Spike. (wgpu_30.rs:101–131; i-slint-renderer-femtovg-1.18.1/images.rs:191–209)
- A wgpu-texture Image draws nothing on the software renderer and panics GL FemtoVG (`unimplemented!()`): never set one on the fallback path. The fallback shows CPU pixels with `SharedPixelBuffer<Rgba8Pixel>` and `Image::from_rgba8_premultiplied`; double-buffer two buffers, because `make_mut_bytes` copies a buffer an Image still holds and pixel Images compare by pointer. Spike. (i-slint-renderer-femtovg-1.18.1/images.rs:34–37; i-slint-core-1.18.1/graphics/image.rs:89–130, 854)
- Slint's own `renderer-vello` feature pulls `vello ^0.10` and `unstable-wgpu-29`: never enable it. `AboutSlint` is exported from `std-widgets.slint` in every style. slint 1.18.1 declares rust-version 1.92; licence `GPL-3.0-only OR LicenseRef-Slint-Royalty-free-2.0 OR LicenseRef-Slint-Software-3.0`.

## Frame timing (the M0 question)

- Slint, winit and wgpu report no vsync count and no presentation time. `RenderingState` carries none; winit has no presentation event; `Adapter::get_presentation_timestamp()` returns *now* on the presentation clock, not a frame's present time; VK_GOOGLE_display_timing, VK_EXT_present_timing and VK_KHR_present_wait are unreachable (no wgpu API, and Slint owns the surface). (wgpu-30.0.1/src/api/adapter.rs:186–209)
- **A rendering notifier makes femtovg-wgpu rebuild its pipelines every frame**: with a notifier Slint flushes twice per frame, and femtovg evicts every pipeline not used in a flush, so each frame recompiles through naga. Spike, release, 10 s spin at 165 Hz on the Radeon 780M: with the notifier the process used 103 % of a core and 149 refreshes went without a new frame (9 %); driving frames from winit's `RedrawRequested` instead, 34 % and 1. (i-slint-renderer-femtovg-1.18.1/lib.rs:246–253, 321–322; femtovg-0.27.0/src/renderer/wgpu.rs:720)
- So drive per-frame work from winit: `slint::Window::on_winit_window_event` (feature `unstable-winit-030`, trait `slint::winit_030::WinitWindowAccessor`) is called for `WindowEvent::RedrawRequested` before Slint's `draw()`. Render the scene there, set the Image, and request the next frame with **winit's** `window.request_redraw()` (via `with_winit_window`): a `slint::Window::request_redraw()` issued there is swallowed, because `draw()` clears Slint's pending flag right after. Spike. (i-slint-backend-winit-1.18.1/winitwindowadapter.rs:841–875, 1258–1290)
- **macOS is different**: on macOS 14+ Slint draws from a CADisplayLink that calls `draw()` without `RedrawRequested`, so the hook does not see those draws; the spike defaults to the notifier there until measured. (i-slint-backend-winit-1.18.1/frame_throttle/apple_display_link.rs:39–49)
- Pacing: Slint configures the surface with `PresentMode::AutoVsync` on every resize (Fifo on Wayland, FifoRelaxed on XWayland) and `desired_maximum_frame_latency: 2`, with no API or variable to change either. The CPU blocks in `get_current_texture()` inside `draw()`, after the hook. On X11 and Windows Slint paces its own redraws with a timer of `1_000_000 / refresh_mHz` whole milliseconds (6 ms at 144 and 165 Hz, 10 ms at 100 Hz); a winit `request_redraw` from the hook bypasses it. Femtovg-wgpu never calls `pre_present_notify()` (calling it halved the frame rate). Spike. (i-slint-renderer-femtovg-1.18.1/wgpu.rs:332–346; i-slint-backend-winit-1.18.1/frame_throttle.rs:13–98)
- The timestamp to count vsyncs from is the hook's `Instant::now()`: in steady state it sits within ±0.1 period of a fitted grid. The first frames after idleness come in a burst while the swapchain refills (intervals of 9.1, 6.7, 4.6, 3.3 ms at a 6.07 ms period) and each is still shown on its own refresh. Spike.
- The nominal refresh rate is not the real one: winit reports 165001 mHz, the compositor 6.0605 ms, hardware vblanks 6.0718 ms (164.70 Hz, 0.19 % slower). Fit the period online, or animated time drifts from the wall clock (and from audio scheduled on it) by ~19 ms per 10 s. `MonitorHandle::refresh_rate_millihertz()` comes from the current mode on Wayland (`None` until the surface enters an output), X11 and macOS, and in whole Hz on Windows (59.94 Hz reads 59000 or 60000). Spike. (winit-0.30.13/src/platform_impl/linux/wayland/output.rs:79–84; windows/monitor.rs:179–193)
- Display latency from the hook to the frame on screen: 24–30 ms (4–5 refreshes) on the wgpu path, 13 ms with GL FemtoVG (vello_cpu fallback). Spike, via wp_presentation.
- On Wayland, `wp_presentation` (wayland-protocols 0.32.13) is reachable through a guest wayland-client connection on winit's `wl_display` (`Backend::from_foreign_display`) with an event queue of its own: per frame it gives the display's vsync counter (MSC) and a hardware timestamp on CLOCK_MONOTONIC, the ground truth for dropped frames. It adds no crates (winit already depends on them). Request feedback before Slint's commit (in the hook); it arrives 4–5 refreshes later. Spike (`spike/src/present.rs`).

## Vello

- vello 0.11.0 requires `wgpu ^30.0.0`, declares MSRV 1.89, calls itself alpha, needs compute shaders and has no blur or filter effects yet. velato 0.12.0 (Lottie) still depends on `vello ^0.10`.
- `Renderer::new(&Device, RendererOptions { use_cpu, antialiasing_support, num_init_threads, pipeline_cache })` and `render_to_texture(&Device, &Queue, &Scene, &TextureView, &RenderParams { base_color, width, height, antialiasing_method })`: it takes a **view** (the crate doc's example is stale) of an `Rgba8Unorm` texture with `STORAGE_BINDING`, and submits on the queue without polling, so later work on the same queue is ordered after it. Use `AaSupport::area_only()` unless MSAA is needed. Keep `num_init_threads: None` on Linux and Windows: single-threaded pipeline creation took 2.5–5.7 s on NVIDIA against ~130 ms. Spike. (vello-0.11.0/src/lib.rs:373–483; wgpu_engine.rs:179–190)
- Output is **straight alpha**, blended on sRGB-encoded values (50 % white over black reads 128). Spike. (vello_shaders-0.11.0/shader/fine.wgsl:1386–1396)
- `Limits::default()` and no features suffice (it needs ≥ 8 storage buffers per stage, ≥ 1 storage texture, ≥ 256 invocations per workgroup). `Renderer::new` returns `Ok` even when every pipeline failed validation; the error then panics through wgpu's uncaptured-error handler, on a worker thread. Before taking the Vello path check `adapter.get_downlevel_capabilities().flags` for `COMPUTE_SHADERS` and `wgpu::Limits::default().check_limits(&adapter.limits())`. Spike.
- Colour emoji: `draw_glyphs` paints COLRv1, COLRv0 and bitmap (sbix, CBDT, EBDT) glyphs with no feature flag, but **re-expands COLR glyphs on the CPU at every call** (1000 emoji: 88 ms). Encode static content once into a retained `Scene` and add it per frame with `scene.append(&retained, Some(transform))` (0.4 ms for 218k segments). `brush_alpha` is ignored for COLR glyphs (fade them with a layer), and the source flags sweep gradients as upside down: the Noto 🇮🇹 renders visibly darker than on vello_cpu. Spike. (vello-0.11.0/src/scene.rs:605–689, 937–1192)
- `vello::Glyph { id, x, y }`, `NormalizedCoord = i16`, glyph y is the baseline (down). `peniko::FontData` is `linebender_resource_handle::FontData { data: Blob<u8>, index }`, the same type in vello, vello_cpu and parley; `Blob` equality and the glyph caches key on the blob id, so keep one `FontData` per file. kurbo: `Affine::rotate` and `CircleSegment` angles run clockwise on a y-down screen, 0 at 3 o'clock. Spike.

## vello_cpu 0.3.0

- Its own API: `RenderContext::new_with(w: u16, h: u16, RenderSettings { level, num_threads })`, one `Resources` per context; state setters (`set_transform`, `set_paint`, `set_stroke`, `set_fill_rule`), `fill_path(&BezPath)`, `stroke_path`, `glyph_run(&mut resources, &font)` (it captures the transform and paint at the call: set them first; `.hint()` defaults to **true**, unlike Vello), `flush()` (mandatory before rendering with threads), `render_with(target: impl Into<PixmapMut>, &mut resources, RasterizerSettings { target_init: TargetInit::Clear(color), .. })`. Output is **premultiplied** RGBA8; render straight into Slint's buffer through `PixmapMut::new(w, h, bytes)`. `reset()` restores the default state. Spike. (vello_cpu-0.3.0/src/render.rs:170–950)
- kurbo, peniko, color and `FontData` are the same types as Vello's, but `vello_cpu::Glyph`, `vello::Glyph` and `parley::Glyph` are three structs: map per backend. Worker ids are a `u8`: more than 255 threads panic. Sides near 65535 overflow: keep frames well below. Filters panic in multi-threaded mode.
- Spike, release, 2135×1367 at scale 1.67 in the window: 12 labelled slices in 0.36 ms of encoding and 0.53 ms of rasterization with 4 threads; 1000 slices at 2560×1600 in 4.5 ms (4 threads), 15 ms single-threaded.

## Parley 0.12.0

- Split into `parley` (styles, builders, `Layout`; re-exports `fontique` and `FontData`), `parley_engine` (analysis, shaping with harfrust, `Glyph`) and `parlance` (vocabulary types). swash is no longer used. `FontContext { collection, source_cache }`; `LayoutContext<B: Brush>` (use `()`: `peniko::Color` has no `Default`). Build with `ranged_builder(&mut fcx, text, 1.0, false)` (scale 1, no quantizing: wheel labels rotate), `break_all_lines(None)` for one line. Spike.
- **Never put a generic family in a label stack on Linux**: a generic expands to fontconfig's whole sorted list (50+ families), which outranks script fallbacks: monochrome Symbola emoji, FreeSans Devanagari, Liberation Mono Hebrew. Name the families (Noto Sans, Noto Color Emoji) and pin script fallbacks with `collection.set_fallbacks(FallbackKey::new(script, None), ..)`. A missing named family is dropped silently: check `collection.family_id(name)`. Register bundled fonts from memory (`register_fonts(Blob::from(bytes), None)`) so blob ids stay stable, and use `SourceCache::new_shared()` so evicted system fonts come back with the same blob. Spike. (parley-0.12.0/src/shape/mod.rs:305–442; fontique-0.12.0/src/collection/mod.rs:182–216)
- The `complex-scripts` feature adds dictionary segmentation for Thai and CJK and silences the debug-build "ICU4X data error" lines; it cost nothing measurable in release. No built-in ellipsis: truncate by clusters in logical order and reshape. `positioned_glyphs()` come out in visual order, so RTL runs draw directly. Shaped lines scale linearly with the size (error 3·10⁻⁵ px): shape once, scale to fit. Linux links fontconfig at build time (`fontconfig-devel`); the `fontconfig-dlopen` feature must then be enabled on Slint's fontique 0.11 as well. Spike.

## wgpu 30.0.1

- API changes met in the spike: `InstanceDescriptor` has a `display` field (use `new_without_display_handle()` or `..._from_env()`); `request_adapter` and `enumerate_adapters` are async and return a `Result` / `Vec`; `request_device(&DeviceDescriptor)` takes one argument; `BufferSlice::get_mapped_range()` returns a `Result`; `device.poll(PollType::wait_indefinitely())` returns a `Result`; `PipelineLayoutDescriptor` has `bind_group_layouts: &[Option<&BindGroupLayout>]` and `immediate_size`. Compute shaders use `textureSampleLevel` (not `textureSample`) and `texture_storage_2d<rgba8unorm, write>`. Spike.
- GPU timing: `Features::TIMESTAMP_QUERY` with pass-level `timestamp_writes`; `queue.get_timestamp_period()` (RADV 10.02 ns per tick, NVIDIA and llvmpipe 1).

## rand 0.10.3

- `gen_range` is now `random_range` on `rand::RngExt`; `rand::Rng` is the dyn-safe core trait (bring it into scope for `next_u64`), so the core's RNG can be injected as `&mut dyn rand::Rng`. Spike. (rand-0.10.3/CHANGELOG.md:63, :160; src/rng.rs:22–34)
- `random_range` on integers is slightly biased unless the `unbiased` feature is on; `Uniform::new(low, high)` returns a `Result` and its `.sample(rng)` is unbiased (Lemire). Spike: a chi-square test over 2·10⁵ draws passes. (src/distr/uniform_int.rs:61, :149, :185–189)
- The OS generator is `rand::rngs::SysRng` (formerly `OsRng`), a unit struct implementing only `TryRng`: `rand::rand_core::UnwrapErr(SysRng)` is an `Rng` that panics if the OS source fails. Seeded tests use a portable generator: `rand::rngs::Xoshiro256PlusPlus` (no feature needed) or `ChaCha8Rng` with the `chacha` feature; `StdRng` and `SmallRng` may change between releases. Spike.
- Fisher–Yates is `rand::seq::SliceRandom::shuffle`; its tiny default bias only touches the order of the entries that were not drawn.

## Kira 0.12.6 (cpal 0.18.2)

- Use `[profile.dev.package."*"] opt-level = 3` (Kira's per-crate list names `symphonia-format-wav`, absent from its tree). Linux needs the ALSA development files at build time even under PipeWire. `cpal-realtime` does nothing on Linux; `cpal-realtime-dbus` needs dbus-devel and is refused for the PipeWire ALSA plugin anyway. Spike.
- Kira has no sample-rate getter: read `cpal::default_host().default_output_device()?.default_output_config()?` (re-exported as `kira::backend::cpal::cpal`) and pass that config in `CpalBackendSettings { device: None, config: Some(..) }` (`device: None` keeps Kira following default-device changes). `StaticSoundData { sample_rate, frames: Arc<[Frame]>, settings, slice }` can be built from synthesized samples. Sound capacity is 128 per track, and scheduled sounds count. Spike.
- Clocks are created stopped (`add_clock(ClockSpeed::TicksPerSecond(1000.0))`, then `start()`); never drop or `stop()` a clock with sounds waiting on it (dropping cancels them, `stop()` rewinds to 0). A sound scheduled with `StartTime::ClockTime` starts at the beginning of the processing chunk in which the clock passes the target: up to `internal_buffer_size` frames early (128 by default, 2.7 ms at 48 kHz). Use `internal_buffer_size: 32` and aim half a chunk late: ±0.33 ms. `ClockHandle::time()` updates once per audio callback (10.67 ms under PipeWire here), so map it to `Instant` with a lower envelope of observations taken at random phases (a frame-locked poller biases it by up to a callback period). Cancel a waiting sound with `stop(Tween { duration: Duration::ZERO, .. })` (the default tween is a 10 ms fade that leaks). Kira exposes no output latency: calibrate per device. Spike (`spike/src/audio.rs`).
